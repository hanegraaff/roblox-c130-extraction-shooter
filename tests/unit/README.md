# Pure rule suites

`Config.spec.luau`, `Validation.spec.luau` and `RateLimit.spec.luau` cover P01/R01/R13 finite inputs, exact boundaries, malformed/oversized payloads and injected-time token accounting. Rejected calls must preserve input or rate state; valid requests still succeed afterward.

`MapRules.spec.luau` adds P02/P13/R05 expanded circle configuration, finite/mismatched geometry settings, inclusive disk boundaries, 720-stud diameter/equal 360-stud radius invariants and sampled orbit positions. It is pure math/configuration evidence; it does not spawn an aircraft or prove world clearance. RoleService.spec.luau adds production population boundaries, exact role counts, seeded rotation and bounded seed validation. RoundRules.spec.luau covers legal phase edges, exact expiry, mutual destruction and noncompetitive empty-server cleanup. AircraftRules.spec.luau adds six P04/R05/R06 cases for periodicity/negative phase wrap, tangent/altitude/perimeter geometry, invalid settings/derived overflow, finite distinct FOVs and inclusive aim boundaries. `BuildingLayout.spec.luau` adds three P13/R16 cases for exact footprints, stories, stairs, IDs and pivots. `AircraftPanRules.spec.luau` adds fourteen P14/R05/R06/R17 cases for local WASD/touch axes, frame-rate independence, input rejection, viewport-corner containment at desktop/phone sizes and both zooms, sustained edge holds, ultra-wide adaptation, rigid orbit-relative view, alternate level geometry and integer reticle rasterization. `PanelDamageRules.spec.luau` adds four P07/R09 cases for heavy-hit 0–6 boundaries, exact nine-second/no-early-transition arithmetic, proportional mixed credit with interruption and invalid/overflow inputs. The current unit suite has 54 cases; these deterministic cases do not establish native keyboard/touch or rendered camera behavior.

Run `lune run scripts/run_tests.luau unit` from the repository root after setup, with Rokit tools on PATH. Each spec returns a function accepting `(test, actualModule)`; it does not copy production rules. The standalone runner discovers these files and loads filesystem modules. The Studio server wrapper registers the same cases with TestEZ using mapped ModuleScripts, proving dependency loading in both runtimes.

Authoritative RoleService/RoundRules load from the server package in Lune and Studio; they are not replicated for testing. Add deterministic gameplay rule cases as their plans implement them. Inject clocks/randomness and test observable boundaries rather than private implementation details.
