# Lifecycle, match and aircraft-selection integration suites

`Lifecycle.spec.luau` covers P01/R01/R15 by composing the actual shared lifecycle controller with controlled resource adapters. It checks two start/stop cycles, idempotency, partial-start rollback and retry. Counter-based adapters model owned listeners/tasks; they do not prove engine signal or scheduler behavior.

Run `lune run scripts/run_tests.luau integration` from the root after setup, with Rokit tools on PATH. The Studio server wrapper also registers these same cases against the actual mapped module. Separate Studio specs test engine-owned bootstrap and GUI resources.

MatchService.spec.luau covers P03/R02–R04/R13 with the actual server-only service, an injected clock and observable life-release callbacks. It checks deployment readiness/cancellation, exact deadlines, single-result conflicts, death/reconnect tombstones, operator/ground departures, malformed/stale/replayed/wrong-role commands, three rounds of cleanup, immutable snapshots and bounded seeds. AircraftSelection.spec.luau adds four P04 cases for exact bounded shape/sequence/weapon validation, role rejection, immutable snapshots, accepted traffic after rejection and forced same-round Lobby reset. CombatService.spec.luau adds seven P05 cases for sustained chain-gun readiness, magazine and reload boundaries, switching, invalid/stale fire, weapon-specific range, bounded flight lifetime and an alternate level boundary. DamageRules.spec.luau adds three cases for bounded damage, per-shot target deduplication and invalid inputs. Together the suite has 28 cases. These adapters do not establish engine avatar loading, replication or camera behavior; the multiplayer harness exercises those separately.

Future service suites should connect real services to controlled transport/time/world boundaries. Use real engine suites whenever the claim depends on Instances, raycasts or replication.
