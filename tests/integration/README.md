# Server service integration suites

`Lifecycle.spec.luau` covers P01/R01/R15 by composing the actual shared lifecycle controller with controlled resource adapters. It checks two start/stop cycles, idempotency, partial-start rollback and retry. Counter-based adapters model owned listeners/tasks; they do not prove engine signal or scheduler behavior.

Run `lune run scripts/run_tests.luau integration` from the root after setup, with Rokit tools on PATH. The Studio server wrapper also registers these same cases against the actual mapped module. Separate Studio specs test engine-owned bootstrap and GUI resources.

P25 extends `CombatService.spec.luau` and `LauncherService.spec.luau` with exact 12- and 15-second boundaries, stale and duplicate rejection, and cooldown preservation across weapon switches and launcher transfers. `AircraftHealth.spec.luau` checks the 150/5 damage awards, remaining-health clamp, six surviving rockets and the seventh lethal hit for one Ground player. `MatchService.spec.luau` checks lethal mixed damage in a batch admitted before the deadline. `GroundCombatService.spec.luau` fires more than the former 150-round supply and checks partial and empty magazines, reload timing, retirement and round reset. [P25 acceptance and Studio procedure](../../docs/testing.md#verify-p25-weapon-balance)

MatchService.spec.luau covers P03/R02–R04/R13 with the actual server-only service, an injected clock and observable life-release callbacks. It checks deployment readiness/cancellation, exact deadlines, single-result conflicts, death/reconnect tombstones, operator/ground departures, malformed/stale/replayed/wrong-role commands, three rounds of cleanup, immutable snapshots and bounded seeds. AircraftSelection.spec.luau adds four P04 cases for exact bounded shape/sequence/weapon validation, role rejection, immutable snapshots, accepted traffic after rejection and forced same-round Lobby reset. CombatService.spec.luau adds seven P05 cases for sustained chain-gun readiness, magazine and reload boundaries, switching, invalid/stale fire, weapon-specific range, bounded flight lifetime and an alternate level boundary. CombatViewRules.spec.luau adds five cases covering permitted views, forged/unreachable aim, bounded pose age, vertical edge aim and adaptive FOV caching. DamageRules.spec.luau adds three cases for bounded damage, per-shot target deduplication and invalid inputs. `AircraftHealth.spec.luau` now checks P18’s 1–9 Ground roster maxima, invalid/same/stale reset rejection, fixed rocket/rifle damage, mixed/lethal deduplication and fresh-round restoration. `GroundCombatService.spec.luau` retains rifle readiness/forgery cases; MatchService adds the reverse outcome ordering. `GroundMovementGuard.spec.luau` adds three deterministic movement budget, quarantine and trusted-correction cases. A preflight case checks that invalid or cooldown traffic cannot spend readiness or sequences before geometry. `DestructionService.spec.luau` covers revised P07 per-panel accumulation across pauses, misses, obstruction, target/weapon changes, reload and loss; zero first/resumed credit; no off-target elapsed time; exact stage/mixed thresholds; ordered outcomes/barriers; rejection; cancellation and reset. Interruptions retain earned credit and break timing only. `LauncherService.spec.luau` adds ten P08 cases for atomic raced ownership, malformed/stale/unauthorized/replayed rejection, immutable snapshots, exact reload continuity across transfer/recovery, range/readiness boundaries, multi-shot timing, terminal/reset invalidation and actual MatchService reconnect tombstones with controlled identities. Historical P08/P07 reports retain their original discovery counts; use the current runner/plan record for this candidate. These rule/service rejoin records do not count as an actual same-identity network reconnect. Controlled adapters do not prove actual collision, cosmetic query exclusion, replication or rendered scars.

The P11 structural case fills the accepted-shot window and its interruption
barriers, rejects duplicate or out-of-window outcomes, and verifies ordered
drain, single damage credit and pristine reset. The Studio workload checks
live resource counts during combat and after replays. [P11 procedure](../../docs/testing.md#run-the-p11-performance-harness)

Future service suites should connect real services to controlled transport/time/world boundaries. Use real engine suites whenever the claim depends on Instances, raycasts or replication.
