# Client engine specs

This package is mapped to `ReplicatedStorage.ClientSpecs` only in the test place, so the automatic client runner can load its specs through TestEZ.

It checks real replicated **Test** status, character/HumanoidRootPart availability and environment text in the status GUI. It exercises two explicit start/stop cycles of an independent StatusPanel while preserving the entrypoint panel, then restores the original name. Readiness is staged: successful server fixture completion within 60 seconds, RoundState/role rendezvous within 35 seconds, then a real ready avatar or explicit characterless late-spectator state within 25 seconds. This avoids racing character creation against server-owned fixtures. Timeout diagnostics preserve phase/role/life/load-lease and character/root presence; `ClientTests.StartupReadiness` records actual elapsed and avatar-stage time. These are test-only budgets, not production timing changes.

Foundation’s two cases are P01/R01 shell checks. `PointerGui.spec.luau` adds one P14/R06/R12 case through the production mouse and touch adapters. It creates actual normal, full-bleed and device-safe GUI buttons; checks mouse viewport coordinates and raw GUI-content touch hit tests; and verifies touch conversion with the current GuiInset. For an unblocked world point it compares `ScreenPointToRay` with `ViewportPointToRay` after conversion. It also checks processed and nonfinite touch rejection, actual TextBox focus, mouse window-focus blocking and fixture cleanup. `ClientTests.PointerGuiInset` records the observed inset; the same case checks the actual raster reticle position. `GroundAimGui.spec.luau` adds three P06 cases for raw desktop/native-ray agreement, touch-center reticle/ray layout and owned controller input-mode/cleanup behavior. The current expected total is six client cases. Earlier three-case reports preceded the revised touch adapter and do not prove its new checks passed. Real simultaneous pad and aiming touches require separate operated evidence. P03 role/deadline/UI replication, no-respawn behavior and spectator camera observations live in the separate client RoundHarness after these specs; separate aircraft/thermal probes live in AircraftHarness, combat observations in CombatHarness/GroundCombatHarness and panel-state/opening probes in DestructionHarness. Follow the [testing guide](../../../docs/testing.md) for actual client-context reports and separate stop/restart runs.
