# Client engine specs

This package is mapped to `ReplicatedStorage.ClientSpecs` only in the test place, so the automatic client runner can load its specs through TestEZ.

It checks real replicated **Test** status, character/HumanoidRootPart availability and environment text in the status GUI. It exercises two explicit start/stop cycles of an independent StatusPanel while preserving the entrypoint panel, then restores the original name. Readiness is staged: successful server fixture completion within 60 seconds, RoundState/role rendezvous within 35 seconds, then a real ready avatar or explicit characterless late-spectator state within 25 seconds. This avoids racing character creation against server-owned fixtures. Timeout diagnostics preserve phase/role/life/load-lease and character/root presence; `ClientTests.StartupReadiness` records actual elapsed and avatar-stage time. These are test-only budgets, not production timing changes.

Foundation’s two cases are P01/R01 shell checks. `PointerGui.spec.luau` adds one P14/R06/R12 case through the production mouse and touch adapters. It creates actual normal, full-bleed and device-safe GUI buttons; checks mouse viewport coordinates and raw GUI-content touch hit tests; and verifies touch conversion with the current GuiInset. For an unblocked world point it compares `ScreenPointToRay` with `ViewportPointToRay` after conversion. It also checks processed and nonfinite touch rejection, actual TextBox focus, mouse window-focus blocking and fixture cleanup. `ClientTests.PointerGuiInset` records the observed inset; the same case checks the actual raster reticle position. `GroundAimGui.spec.luau` adds three P06 cases for raw desktop/native-ray agreement, touch-center reticle/ray layout and owned controller input-mode/cleanup behavior. P08 adds a fourth GroundAimGui case that constructs production RoundPanel and GroundCombatController under distinct ScreenGui origins/insets, supplies client-only presentation state representing confirmed rifle/rocket feedback, and checks actual HUD rectangle nonintersection/containment at desktop 1280×720/1920×1080 and phone-sized 568×320/750×381/852×393 layouts. The `ef7826b` header aligns compact summary/health/readiness/ownership regions in shared GUI-content space; touch feedback appears in readiness instead of floating over aim. Checks cover native bottom inventory/thumbstick reserves, the centered reticle, actionable controls, text fit, input-mode transitions and cleanup. A shared cloned coordinate space alone missed the earlier phone inset/header overlap, so historical `0cd6545` host/smoke positives are not phone acceptance. Source `ef7826b` passes all seven client cases in fresh solo Play and on each of two actual SDK clients. Its actual 750×381 and 568×320 iPhone-simulator layout observers, both with 58-pixel inset, report zero owned/native/header/reticle collisions or CoreGui-safe-bound violations, fitting status text and zero-pixel drawn-reticle error; a stricter 567×299 view also passes. Native M-7/ROCKET/DROP/PICK UP/FIRE/RELOAD works at exact 568×320; observed rocket drop/re-pick preserves reload and rejects early fire, and rifle reload transfers 25→30/120→115. Inline HIT readability uses a client-only GroundShot fixture with server aircraft health unchanged at 300. Two QA-camera real rifle aim attempts missed and do not prove damage. These operated and fixture observations remain separate from the final native P08 harness, which passes eleven cases on `07e77ea` against production/UI `ef7826b` with fresh seven-case smoke on all three actual clients. D59 removes unsupported actual same-identity reconnect from acceptance; runtime rejoin protections remain covered by service tests. The supported P08 checks pass, with integration still pending. Earlier three-case reports preceded the revised touch adapter and do not prove its new checks passed. Real simultaneous pad and aiming touches require separate operated evidence. P03 role/deadline/UI replication, no-respawn behavior and spectator camera observations live in the separate client RoundHarness after these specs; separate aircraft/thermal probes live in AircraftHarness, combat observations in CombatHarness/GroundCombatHarness/LauncherHarness and panel-state/opening probes in DestructionHarness.
