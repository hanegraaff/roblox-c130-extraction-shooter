# Client engine specs

This package is mapped to `ReplicatedStorage.ClientSpecs` only in the test place, so the automatic client runner can load its specs through TestEZ.

It checks real replicated **Test** status, character/HumanoidRootPart availability and environment text in the status GUI. It exercises two explicit start/stop cycles of an independent StatusPanel while preserving the entrypoint panel, then restores the original name. Readiness is staged: successful server fixture completion within 60 seconds, RoundState/role rendezvous within 35 seconds, then a real ready avatar or explicit characterless late-spectator state within 25 seconds. This avoids racing character creation against server-owned fixtures. Timeout diagnostics preserve phase/role/life/load-lease and character/root presence; `ClientTests.StartupReadiness` records actual elapsed and avatar-stage time. These are test-only budgets, not production timing changes.

Foundation’s two cases are P01/R01 shell checks. `PointerGui.spec.luau` adds one P14/R06/R12 case through the public production `ThermalCameraController.input` adapter. It creates actual normal/full-bleed GUI buttons, queries their rendered centers using current GuiInset, verifies that returned raw viewport coordinates are unchanged, acquires/releases an actual TextBox focus, checks window-focus blocking and removes all fixtures. `ClientTests.PointerGuiInset` records the observed inset. The current ordinary smoke passes all three cases; earlier two-case reports do not include this regression. Focused actual reticle-raster probes are separate from that three-case total. P03 role/deadline/UI replication, no-respawn behavior and spectator camera observations live in the separate client RoundHarness after these specs; separate aircraft/thermal probes live in AircraftHarness; combat checks remain planned. Follow the [testing guide](../../../docs/testing.md) for actual client-context reports and separate stop/restart runs.
