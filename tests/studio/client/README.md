# Client TestEZ runner

This package’s `init.client.luau` maps to the test-only `StarterPlayerScripts.ClientTests` LocalScript and runs the [client specs](../specs-client/README.md) automatically during Play.

Read `Players.LocalPlayer.PlayerScripts.ClientTests:GetAttribute("ClientTestReport")` in the **client** context. JSON includes suite/environment/seed, discovered/passed/failed/skipped/errors and the actual client `userId`. A missing report, zero discovery or any failed/skipped/error case is incomplete or failed evidence. TestEZ also writes useful details to Studio Output.

Use the [Studio procedure](../../../docs/testing.md#run-the-studio-smoke-suites) to collect both context reports and stop/restart. A server report cannot replace client GUI/replication assertions. This runner and its dependencies never enter the release mapping.

After the foundational specs, `RoundHarness.run()` starts a bounded discovery task for the test-only P03 transport. Automated probes observe the actual LocalPlayer role/life/deadline, RoundHUD and spectator/lobby CameraSubject, send production surrender intent and disconnect through StudioTestService. The listener disconnects when its transport is removed. These observations supplement the current six client TestEZ cases; they are not additional foundation-case counts.

`HumanTestPanel.start()` discovers the test-only session and creates one bottom-right Studio panel. Its role/duration/start/reset/location buttons send bounded server intent tagged with sequence and generation. Server feedback and authoritative attributes drive labels. The GUI persists through character respawn; stopping or removing the session disconnects listeners, cancels pending discovery and destroys the panel. It is never mapped into release builds.

`AircraftHarness.run()` adds P04 actual-client probes through its own excluded transport. It measures replicated canonical pose error, map presence/tangent/altitude, inward operator view, acknowledged weapon/FOV/reticle coherence, singleton ThermalHUD/effect/highlights, original FOV/mouse restoration and real LeaveTest departure. Its transport listener disconnects on removal. Failed probes retain their collected observations. Reticle failures include numeric pixels, viewport/GUI sizes, rendered-frame counts and role/phase/life context while preserving the existing bounds and render timing. Both aircraft harnesses also require the actual drawn reticle center, converted back to viewport space with current GuiInset, to agree with ray pixels within one pixel. These observations supplement the current six client TestEZ cases; rendering occlusion still requires actual visual review. Follow the [P04 procedure](../../../docs/testing.md#run-the-p04-aircraft-harness).

`ExpandedMapHarness.run()` handles P13's excluded test transport. Each actual client compares replicated static map identity/count/shape/flags exactly and CFrame/size numerically within 0.001, checks all building panel IDs/Intact states, queries the eight terrain apex materials/elevations and observes the expanded-perimeter aircraft. It returns the separate foundational client report with each probe and disconnects when transport is removed. These probes cover initial, reset and late-join observations; they do not prove firing, destruction or panning.

`AircraftPanHarness.run()` adds P14 actual-client fixtures. After foundational reports, it stops the ordinary entrypoint through its owned teardown and starts the same production RoundPanel with a nonyielding signed directional-pan/raw-aim-pointer/recenter/profile-intent provider. It never assigns focus. Probes retain same-frame camera/viewport/reticle/surface metadata, including four actual quarter-screen centerline rays inside the current level and downward corner rays, and require real nonflat Terrain slopes and each requested building’s StoryId `02` panel. A 325-CFrame orbit-local basis sweep checks five held views through sampled aircraft phases; the full-orbit probe checks inward bounds at both acknowledged FOVs. Other probes check concurrent operator pan and real Ground humanoid movement with unchanged Ground camera ownership, rejection, blocked/outside input, recenter, thermal configuration and role-loss cleanup. Projection seeks a real first hit on the required surface within the unchanged three-stud target tolerance, using nearby integer pixels if an exact projected point grazes voxel or panel edges; it records diagnostics and can wait for a suitable orbit phase. The transport and fixture panel listeners are removed together.

These written fixtures require the [P14 two-client procedure](../../../docs/testing.md#run-the-p14-panned-targeting-harness). Injected input is automation evidence, not physical input evidence; actual native WASD/touch-pad/aim/keys/buttons, viewport/readability and rendered occlusion require an ordinary session with the default UserInputService path. The P06 expected ordinary smoke has six client cases, including the expanded mouse/touch PointerGui adapter check and the GroundAimGui reticle/ray agreement case. Earlier smoke reports predate that touch change and are not evidence for its new assertions. A separate real two-touch check is needed to verify pad and aim ownership, along with full-orbit native-input and rendered/UI acceptance.

The test-only `CombatHarness` client observes weapon/readiness, shot/impact, health and result state and sends bounded fire/selection probes for the two-client P05 harness. Its excluded transport is destroyed on teardown; actual execution and acceptance are recorded in the [P05 plan](../../../plans/05-gunship-combat.md), separate from the ordinary six client TestEZ cases.

The test-only `GroundCombatHarness` client sends bounded rifle intents and observes replicated shot, health, destruction and result state for P06. It is excluded from release builds and its listeners are removed on teardown. Native desktop input and simulated-phone layout received separate operated review on the current source; physical-device behavior remains unverified.

`GroundAimGui.spec.luau` checks desktop mouse and touch-center aim using real GUI layout, measured inset and viewport camera rays; it also checks touch label placement and an actual owned controller reacting to input-mode changes and cleaning up. Its passing result supplements, but does not replace, an operated native moving-aircraft aim/fire review.

The test-only `DestructionHarness` discovers `P07Harness`, sends bounded production fire/selection intents and reports replicated stage/progress/part-count/pivot/opening observations. It can issue a finite 61-request 30mm burst with a 0.18-second send interval, rebuilding each request from the current permitted view immediately before sending and recording bounded send timestamps. This test delivery margin preserves the production 0.15-second cadence and 0.225-second continuity gap; client send time does not award credit. It can also move the actual ground Humanoid through a damaged opening, confirm expired fragments and observe late-spectator role/life/equipment. Client state waits are bounded to eight seconds, progress tolerance is 1e-5 and pivot-position tolerance 0.01 studs. It never supplies panel damage or authoritative duration. Its listener disconnects when the transport is removed. These probes supplement the unchanged six client baseline cases; they do not prove physical input or rendered thermal readability. See the [P07 procedure](../../../docs/testing.md#run-the-p07-destruction-harness).
