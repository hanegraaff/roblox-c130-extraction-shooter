# Client status, round HUD, thermal view and spectating

Rojo maps this package to `StarterPlayer.StarterPlayerScripts.Client`. The entrypoint waits up to ten seconds each for PlayerGui and bootstrap status, then starts `StatusPanel`. It attaches one `RoundPanel` to RoundState and replaces it when the server owner changes. Removal/script destruction releases owned controllers and listeners. Missing initial readiness produces an assertion instead of silent startup.

`StatusPanel.new(playerGui, status)` returns an idempotent [Lifecycle](../shared/README.md) controller. Starting owns one FoundationStatus ScreenGui and attribute listener displaying environment/running state. Stopping disconnects and destroys both. ResetOnSpawn is false so character replacement cannot duplicate the panel.

`RoundPanel.new(player, playerGui, state, inputProvider?, touchProvider?)` returns a nonyielding lifecycle controller. The fourth argument remains the optional thermal input provider; the fifth is an optional nonyielding touch-capability provider for alternate environments/tests. Production samples UserInputService. Starting owns one RoundHUD, a **Surrender / spectate** button, heartbeat, destruction listener and ThermalCameraController. Before writing camera state it checks whether the thermal owner currently owns the view. The HUD displays phase, role/life, ground count, result and a countdown from the authoritative deadline using GetServerTimeNow. The button appears only for living active ground players and sends the current round ID with an increasing per-round sequence; server validation decides whether it takes effect. Active Ground touch mode uses the compact D58 header; nonactive guidance correctly says ground players start with the M-7 and one launcher is on the map.

During Active, eliminated players and late spectators follow the lowest-UserId living ground teammate. Without a target, the camera uses a fixed map overview. Lobby resumes the local character camera. Stop restores Custom camera mode and the local Humanoid when available, disconnects listeners and destroys the HUD. The entrypoint reattaches on server owner replacement rather than keeping stale state.

`ThermalCameraController.new(player, playerGui, roundState, inputProvider?)` immediately installs a nonyielding client owner exposing `ownsCamera()` and idempotent `stop()`. An active living Gunship player receives a Scriptable camera at the replicated canonical Hitbox. The camera holds an orbit-local pan offset: when input stops, its angle relative to the C-130 stays fixed as the aircraft circles. A labelled solo Operator preview in the excluded test mapping uses the same view while retaining Waiting/Lobby. Each entry owns one ThermalHUD, ColorCorrectionEffect, role input listener, profile buttons and one occluded Highlight per eligible ground character/tagged thermal fixture. Touch devices also own one `OperatorTouchControls` ScreenGui using device-safe insets for the pad, profile, Fire and Recenter buttons; the full-viewport ThermalHUD retains exact reticle/ray coordinates.

Keys 1/2 or named buttons send bounded production selection intent; the current 30° GAU23 / 40° M102 FOV defaults and reticle projection update from the atomic acknowledged Selection string for the current round. Rejected selection does not optimistically change zoom. Solo preview profile choice is cosmetic. Operator WASD and the four touch-pad buttons feed the same signed camera-relative `AircraftPanRules.step` input. A and the left arrow move the camera left; D and the right arrow move it right. Diagonal speed normalizes to 120 studs/second and each update caps elapsed time at 0.1 seconds. The wide lens bounds pan for both profiles, preserving the same relative angle through selection. On unusually wide viewports, the lens can narrow to keep the bounded view valid. The level edge can enter roughly the outer quarter of each viewport centerline at the wide lens; curved edges may extend farther inward at corners, while the tighter lens shows less beyond the edge. Corner rays still point down and the view remains short of straight down. Ground WASD remains movement. Mouse movement aims only; on touch a second finger on the world view aims while a directional button is held. R / Recenter or fresh role/new-round entry returns to a safe default inward view. The displayed reticle is rounded/clamped once through `AircraftPanRules.raster` to 15–85% of X/Y, then used for camera ray and published pixels. `ThermalCameraController.guiOffset` converts that viewport pair through the measured ScreenGui origin for drawing, including mobile safe-area offsets. The camera raycasts actual collidable Battlefield/Terrain surfaces; a miss or endpoint outside the disk/authored Y envelope is marked invalid. Actionable desktop UI hover, text focus and window focus loss suspend pan. There is no free flight, independent zoom or pan remote.

`ThermalCameraController.frame(position, focus)` returns a finite inward CFrame or nil for invalid/outward geometry. The focus is the world-space ground point obtained by rotating the held orbit-local offset with the aircraft position. It projects canonical orbit-right into the look plane for a stable basis. The optional nonyielding `InputProvider(viewport)` returns `{ position: Vector2, blocked: boolean, panRight: number?, panUp: number?, recenter: boolean?, weapon: string? }`; aim coordinates are raw viewport pixels and pan axes are signed −1…1. Production omits it and samples UserInputService. The P14 fixture stops the ordinary owner before constructing the same RoundPanel with injected input; this automation is separate from native keyboard/touch review.

The active operator camera owns a scaled, flat visual backdrop below the playable disk. It has no collision, touch, ray-query or shadow behavior, is never server-authored, and is destroyed with the camera owner on role loss or stop. Its size and the pan limit share `AircraftPanRules.backdropHalfExtent` so downward corner rays remain covered through the orbit. The actual playable disk and server aim validation are unchanged.

`ThermalCameraController.input(playerGui, rawPointer, windowFocused)` samples the desktop pointer/UI boundary without yielding. It returns the raw viewport pointer unchanged and a blocked flag for window/text focus, actionable GUI overlap or nonfinite pixels. Only the mouse GUI hit query subtracts the current top-left `GuiService:GetGuiInset()`; drawn-reticle and ray coordinates remain in viewport space.

`ThermalCameraController.touchViewportPosition(point)` converts a touch `InputObject.Position` from GUI-content to viewport pixels by adding the current `GuiInset`. It returns nil for nonfinite input or result and does not yield. `touchInput(playerGui, point, processed)` hit-tests the raw GUI-content point, returns the converted viewport position, and marks the frame blocked for processed input, a focused text box, an actionable GUI object or invalid coordinates. A touch on the pad cannot claim world aiming. If GUI and global callbacks arrive in either order, pad capture releases any accidental aim ownership and restores the prior aim position. A separate unprocessed world touch owns aiming until it ends; only its changes update the converted aim position. Focus loss clears held pad directions and the active aim-touch ownership; role loss or stop also clears the stored aim and disconnects all touch listeners. A fresh pad touch restores focus after a Studio/device window transition.

`guiOffset(pixels, guiOrigin)` returns integer GUI-local UDim2 offsets or nil for nonfinite coordinates; the GUI origin is measured from an owned zero-size Frame plus current GuiInset.

ThermalHUD attributes commit `PanFocus` (world point), `PanLocalFocus` (held orbit-local point), `PanDirection`, `ProjectionGuiOrigin`, `RawPointer`, `InputBlocked`, `ProjectionViewport`, `ProjectionFrame`, `ProjectionTime`, `ProjectionCamera`, `ProjectionHit`, `AimEndpoint`, `ReticlePixels`, `Weapon`, `FOV` and `AimAllowed` for observation. They are local presentation diagnostics, not hit authority.

Role loss, missing state/aircraft or camera replacement removes GUI, post-processing, highlights and role input connections, restoring captured camera/FOV/mouse settings. The controller's RenderStepped observer remains only until its RoundPanel owner stops; stop disconnects it and is idempotent. RoundPanel resumes normal ground/spectator/lobby camera behavior. No thermal state controls collision, authority or damage.

During an active operator life, holding left mouse or the touch Fire button sends bounded target intent when the reticle has a valid aim point; solo preview cannot fire. The HUD presents the acknowledged weapon and replicated ammo or reload timer. The request includes a view claim for server-side reachable-view validation; it does not attest the actual client camera. The server owns flight, impact and damage; client projection and indicators do not authorize them. These controllers do not assign roles, grant lives or commit results. RoundPanel supplies a dedicated replicated aircraft-health readout for both active roles. Manual spectator target selection and combat audio remain planned. P07 changes server-replicated world panels; these controllers retain no structural authority. Thermal and aim world queries use actual Battlefield/Terrain geometry and exclude physical fragments through their query boundary.

## Ground rifle and launcher

`GroundCombatController.new(player, playerGui, roundState, touchProvider?)` returns a nonyielding idempotent Lifecycle owner. It owns one GroundCombatHUD and listeners for an active living Ground player. The optional nonyielding provider controls input-mode tests; production samples UserInputService. Role/round changes, unequip, focus loss or stop release held input; stop disconnects listeners and destroys the GUI.

Desktop aim uses raw mouse viewport pixels; touch aim uses viewport center. `projectAim` rounds one pixel for ray and reticle and uses the measured GUI origin plus inset only for drawing. The equipped server-owned M-7 or launcher Tool chooses fire intent. Native tool slots select equipment; carriers on touch use M-7/ROCKET buttons. Hold left click or FIRE; R/RELOAD applies only to the M-7, while launcher reload is automatic. Ammo and reload timing come from replicated Tool attributes, so selection cannot refill a weapon.

LauncherState’s atomic Snapshot supplies current round/identity/owner/position/readiness presentation. E/PICK UP sends bounded acquisition intent; G/DROP releases a carried launcher. Nearness controls the prompt only; the server still checks reach, geometry, membership, life and movement. All ground teammates see available/carried status. A carrier retains its M-7. The desktop pickup and launcher-status rows sit above ammunition, with all three above the reserved native inventory region. Active Ground touch presentation shares a compact header across RoundHUD and GroundCombatHUD: summary/surrender first, then aircraft health left and weapon readiness right, then launcher ownership left. The 240×22-pixel health/readiness row occupies shared GUI-content Y=44–66; ownership uses Y=70–92. GroundCombatHUD measures its content origin and current inset each frame to align with the normally inset RoundHUD; raw viewport coordinates remain reserved for aim rays. `statusLayout(touch, origin?, inset?)` returns readiness position/size in that GUI-content space without yielding. Touch FIRE is 78×56 and RELOAD 54×42 in the upper right; 68-pixel-wide equipment actions remain below the reticle and above the 96-pixel native inventory reserve. These are D58 tuning defaults on `ef7826b`; desktop/operator framing, input and server authority are unchanged. Ownership loss or a new round clears local readiness/input assumptions. Clients do not clone authoritative equipment.

Current-round server-resolved rifle shots flash the shooter’s reticle. On desktop, confirmed rifle damage shows AIRCRAFT HIT −5 for 1.2 seconds; launcher LastImpact shows ROCKET HIT only for a server-confirmed direct hit by that shooter. On touch, either confirmed hit appends HIT to the compact readiness row instead of drawing floating hit text over the centered reticle. RoundPanel’s shared aircraft-health readout is the team’s damage guide; the HUD does not promise a fixed remaining rocket count after rifle damage. Presentation cannot authorize hits, ownership, collision or results.

`GroundAimGui.spec.luau` checks real ray/reticle alignment, mode changes, cleanup and production-created HUD rectangle separation/containment at desktop and phone sizes. The layout case constructs both production RoundPanel and GroundCombatController under distinct ScreenGui origins/insets, supplies client-only presentation state representing confirmed rifle/rocket feedback and checks shared coordinates, hit text, centered aim, native inventory/thumbstick reserves and teardown. This catches cross-ScreenGui overlap that a shared cloned coordinate space misses. Actual native CoreGui/simulator measurements remain separate, since Studio captures omit the hotbar. These fixtures supplement native mouse/keyboard/touch and moving-aircraft review. [P06](../../plans/06-ground-combat.md) retains earlier source-specific aiming/tracer evidence; [P08](../../plans/08-rocket-launcher.md) records eleven native harness cases passing on test source `07e77ea` with three actual clients and unchanged `ef7826b` presentation. D59 removes unsupported actual same-identity reconnect from acceptance; runtime rejoin protections remain covered by service tests. The supported P08 checks pass, with integration still pending. The excluded client LauncherHarness sends production pickup/drop/fire intent and observes actual replicated ownership/reload/health; it is not shipped input code.
