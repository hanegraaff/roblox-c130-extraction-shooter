# Client status, round HUD, thermal view and spectating

Rojo maps this package to `StarterPlayer.StarterPlayerScripts.Client`. The entrypoint waits up to ten seconds each for PlayerGui and bootstrap status, then starts `StatusPanel`. It attaches one `RoundPanel` to RoundState and replaces it when the server owner changes. Removal/script destruction releases owned controllers and listeners. Missing initial readiness produces an assertion instead of silent startup.

`StatusPanel.new(playerGui, status)` returns an idempotent [Lifecycle](../shared/README.md) controller. Starting owns one FoundationStatus ScreenGui and attribute listener displaying environment/running state. Stopping disconnects and destroys both. ResetOnSpawn is false so character replacement cannot duplicate the panel.

`RoundPanel.new(player, playerGui, state, inputProvider?)` returns a nonyielding lifecycle controller. Starting owns one RoundHUD, a **Surrender / spectate** button, heartbeat, destruction listener and ThermalCameraController. Before writing camera state it checks whether the thermal owner currently owns the view. The HUD displays phase, role/life, ground count, result and a countdown from the authoritative deadline using GetServerTimeNow. The button appears only for living active ground players and sends the current round ID with an increasing per-round sequence; server validation decides whether it takes effect.

During Active, eliminated players and late spectators follow the lowest-UserId living ground teammate. Without a target, the camera uses a fixed map overview. Lobby resumes the local character camera. Stop restores Custom camera mode and the local Humanoid when available, disconnects listeners and destroys the HUD. The entrypoint reattaches on server owner replacement rather than keeping stale state.

`ThermalCameraController.new(player, playerGui, roundState, inputProvider?)` immediately installs a nonyielding client owner exposing `ownsCamera()` and idempotent `stop()`. An active living Gunship player receives a Scriptable camera at the replicated canonical Hitbox. The camera holds an orbit-local pan offset: when input stops, its angle relative to the C-130 stays fixed as the aircraft circles. A labelled solo Operator preview in the excluded test mapping uses the same view while retaining Waiting/Lobby. Each entry owns one ThermalHUD, ColorCorrectionEffect, role input listener, profile buttons and one occluded Highlight per eligible ground character/tagged thermal fixture. Touch devices also own one `OperatorTouchControls` ScreenGui using device-safe insets for the pad, profile and Recenter buttons; the full-viewport ThermalHUD retains exact reticle/ray coordinates.

Keys 1/2 or named buttons send bounded production selection intent; the current 30° GAU23 / 40° M102 FOV defaults and reticle projection update from the atomic acknowledged Selection string for the current round. Rejected selection does not optimistically change zoom. Solo preview profile choice is cosmetic. Operator WASD and the four touch-pad buttons feed the same signed camera-relative `AircraftPanRules.step` input. Diagonal speed normalizes to 120 studs/second and each update caps elapsed time at 0.1 seconds. The wide lens bounds pan for both profiles, preserving the same relative angle through selection. On unusually wide viewports, the lens can narrow to keep the bounded view valid. The level edge can enter roughly the outer quarter of each viewport centerline at the wide lens; curved edges may extend farther inward at corners, while the tighter lens shows less beyond the edge. Corner rays still point down and the view remains short of straight down. Ground WASD remains movement. Mouse movement aims only; on touch a second finger on the world view aims while a directional button is held. R / Recenter or fresh role/new-round entry returns to a safe default inward view. The displayed reticle is rounded/clamped once through `AircraftPanRules.raster` to 15–85% of X/Y, then used for camera ray and published pixels. `ThermalCameraController.guiOffset` converts that viewport pair through the measured ScreenGui origin for drawing, including mobile safe-area offsets. The camera raycasts actual collidable Battlefield/Terrain surfaces; a miss or endpoint outside the disk/authored Y envelope is marked invalid. Actionable desktop UI hover, text focus and window focus loss suspend pan. There is no free flight, independent zoom or pan remote.

`ThermalCameraController.frame(position, focus)` returns a finite inward CFrame or nil for invalid/outward geometry. The focus is the world-space ground point obtained by rotating the held orbit-local offset with the aircraft position. It projects canonical orbit-right into the look plane for a stable basis. The optional nonyielding `InputProvider(viewport)` returns `{ position: Vector2, blocked: boolean, panRight: number?, panUp: number?, recenter: boolean?, weapon: string? }`; aim coordinates are raw viewport pixels and pan axes are signed −1…1. Production omits it and samples UserInputService. The P14 fixture stops the ordinary owner before constructing the same RoundPanel with injected input; this automation is separate from native keyboard/touch review.

The active operator camera owns a scaled, flat visual backdrop below the playable disk. It has no collision, touch, ray-query or shadow behavior, is never server-authored, and is destroyed with the camera owner on role loss or stop. Its size and the pan limit share `AircraftPanRules.backdropHalfExtent` so downward corner rays remain covered through the orbit. The actual playable disk and server aim validation are unchanged.

`ThermalCameraController.input(playerGui, rawPointer, windowFocused)` samples the desktop pointer/UI boundary without yielding. It returns the raw viewport pointer unchanged and a blocked flag for window/text focus, actionable GUI overlap or nonfinite pixels. Only the GUI hit query subtracts the current top-left `GuiService:GetGuiInset()`; drawn-reticle and ray coordinates remain in raw viewport space. `guiOffset(pixels, guiOrigin)` returns integer GUI-local UDim2 offsets or nil for nonfinite coordinates; the GUI origin is measured from an owned zero-size Frame plus current GuiInset. The touch path keeps per-finger pad holds and one separate aiming touch; a fresh pad touch restores focus after a Studio/device window transition. All touch listeners and holds are cleared on role loss/stop.

ThermalHUD attributes commit `PanFocus` (world point), `PanLocalFocus` (held orbit-local point), `PanDirection`, `ProjectionGuiOrigin`, `RawPointer`, `InputBlocked`, `ProjectionViewport`, `ProjectionFrame`, `ProjectionTime`, `ProjectionCamera`, `ProjectionHit`, `AimEndpoint`, `ReticlePixels`, `Weapon`, `FOV` and `AimAllowed` for observation. They are local presentation diagnostics, not hit authority.

Role loss, missing state/aircraft or camera replacement removes GUI, post-processing, highlights and role input connections, restoring captured camera/FOV/mouse settings. The controller's RenderStepped observer remains only until its RoundPanel owner stops; stop disconnects it and is idempotent. RoundPanel resumes normal ground/spectator/lobby camera behavior. No thermal state controls collision, authority or damage.

These controllers present server facts; they do not assign roles, grant lives or commit results. Firing/ammunition/health HUDs, manual spectator target selection, combat effects and audio remain planned.
