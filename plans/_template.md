# PNN — Capability name

**Milestone:** name. **Dependencies:** plan IDs. **Requirements:** requirement IDs. Status belongs in [roadmap](../roadmap.md).

## Capability and player experience

Describe the single capability and what a human can do/see after completion. State what is outside this increment when necessary to keep it coherent.

## Implementation

Name relevant source boundaries, data/authority contracts and integration points. Resolve required decisions or label blockers; do not prescribe every line of code.

## Acceptance criteria

Use stable A1, A2, … IDs. State observable results and named intended automated suites, boundary/negative cases, required engine checks and the full applicable gate. Distinguish automation from focused human judgment.

## Focused human check

Describe only the visual/interaction evidence automation cannot establish. State viewpoints, client count and important scenarios.

## Documentation changes

List the coherent current-capability narrative, API contracts and contributor instructions that change.

## Completion record

Record criterion → actual test/command → environment → observed result, source commit/tree, CI/PR links, Studio report, tester findings, documentation review and remaining blockers. Leave unrun checks explicitly unrun.
